# M. tuberculosis loci where recurrent variant calls are usually alignment
# artifacts rather than mutations.
#
# ---------------------------------------------------------------------------
# WHY THIS IS A SEPARATE LIST FROM tb_resistance_genes.txt
#
# Both lists get masked, but for different reasons, and keeping them apart
# keeps each one auditable.
#
#   tb_resistance_genes.txt  masks loci under convergent SELECTION.  The
#                            variants there are real; they recur because the
#                            same mutation is selected over and over.
#
#   this list                masks loci where the variants are largely NOT
#                            real.  They recur because short reads cannot be
#                            placed unambiguously: paralogous gene families,
#                            repeats, prophages.
#
# Mixing them would hide which rationale applies to which gene, and the two
# need different masking parameters (see below).
#
# tb_repair_genes.txt is the opposite of both: DO NOT mask those.
#
# ---------------------------------------------------------------------------
# USE A SYMMETRIC PAD, NOT A PROMOTER FLANK
#
# Artifacts spill past a feature's annotated edges in BOTH directions, so
# --promoter_flank (upstream only) does not contain them.  Use --mask_pad:
#
#   annotate_sites.py --annotation NC_000962.3.gff3.gz \
#       --regions tb_alignment_loci.txt \
#       --mask_pattern '^(PE|PPE|esx)' \
#       --mask_product_pattern '(?i)(transposase|integrase|insertion element|^maturase$)' \
#       --mask_pad 150 --mask_matutils matUtils_mask.txt
#
# On a 129k-sample MTBC tree, nine of the twenty most recurrent surviving sites
# sat 1-56 bp OUTSIDE a feature, seven of them downstream, where a promoter
# flank reaches nothing.  100 bp of symmetric pad covered all nine.
# A later round widened it to 150 for the Rv2019 cluster (see below).
#
# The two lists can go in one mask, but they want different widening, so
# resolve them separately and concatenate the BED files:
#
#   ... --regions tb_resistance_genes.txt --promoter_flank 200 --mask_bed a.bed
#   ... --regions tb_alignment_loci.txt   --mask_pad 100       --mask_bed b.bed
#
# ---------------------------------------------------------------------------
# GENE NAMES AND LOCUS TAGS, NO COORDINATES.  Every interval is resolved from
# the annotation you supply.  A name that is not in your annotation is reported
# as NOT FOUND, which is harmless.  Verify anything you rely on against
# Mycobrowser or the NCBI H37Rv annotation; the Rv ranges in comments below are
# the parts most worth checking, because a range I have misremembered would
# mask the wrong sequence silently.
#
# Prefer --mask_pattern for the big families (it matches names, so it picks up
# members this file has not listed) and use the entries here for the specific
# genes and the prophages.
# ---------------------------------------------------------------------------

# --- insertion sequences, transposases and integrases ------------------------
# IS6110 is present in 1-25 copies depending on the strain, so its reads have
# nowhere unambiguous to go.  IS1081 and the IS21/IS256 families likewise.
#
# Reach these by PRODUCT rather than by name -- named members vary between
# annotations, and the H37Rv listing above turned up an integrase at Rv2646,
# well outside either prophage, that no name-based list would have caught:
#     --mask_pattern '(transposase|integrase|IS[0-9]+|insertion element)'
#
# ADD maturase to that pattern.  Rv0071 is annotated "maturase", carried 224
# events after the first full mask, and no name or product pattern above
# reaches it.  The two maturase locus tags this file guessed (Rv1764, Rv2105)
# are NOT FOUND in NC_000962.3, so the product is the only reliable route:
#     --mask_product_pattern '(?i)(transposase|integrase|insertion element|^maturase$)'
#
# --mask_pattern matches gene names and locus tags, NOT products, so use
# --mask_product_pattern for these.  That is the point of it: a transposase
# annotated only as Rv2648 cannot be reached by any name-based pattern, and the
# loci most worth masking for alignment reasons are exactly the ones with
# uninformative names.
#
# Nothing needs to be listed here as a result -- the pattern finds them all,
# including members this file has never heard of.
#
# If you save a product-pattern run's locus list to a file and then feed that
# file back in with --regions, the flag becomes redundant: the names already
# cover the same loci and the mask does not change.  On NC_000962.3 the pattern
# matched 40 loci and a saved 40-name list reproduced the mask exactly, to the
# base.  Keep passing the flag anyway -- the saved names are specific to one
# annotation, the pattern is what carries over to the next one.  Rv2646 is kept only as a
# worked check: an integrase outside either prophage, which name matching
# missed and product matching found.
Rv2646

# --- specific recurrent sites seen on a 129k-sample MTBC tree -----------------
# Not members of a known repeat family, but each carried hundreds of events
# after resistance loci were masked.  Listed so the mask is reproducible, NOT
# because the mechanism is established: ponA1 631, hsdM 306 and Rv2024c 507 are
# nonsynonymous at every alternate and so are as likely to be convergent
# selection as artifacts.  Either way they break the chi-squared test's
# independence assumption and belong in a mask -- but if you are hunting for
# the biology, look at them before you mask them.
#
# Note what these entries cost.  Several were reached from a hotspot that is
# INTERGENIC, 1-56 bp outside the gene, so masking the gene removes a few
# thousand bases of real coding sequence to remove a few hundred artifactual

# independence, but it is a trade, and masking the position alone does not
# work: the next profile surfaces its neighbour.
#
