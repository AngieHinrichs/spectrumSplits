# M. tuberculosis DNA repair, replication-fidelity and dNTP-pool genes.
#
# ---------------------------------------------------------------------------
# DO NOT MASK THESE.
#
# This list is the opposite of tb_resistance_genes.txt in purpose.  Resistance
# loci are masked because recurrent selected mutations there corrupt the
# spectrum.  Repair-gene mutations are the EXPLANATION you are looking for when
# a clade turns out to have a distinct spectrum: a lineage that lost or altered
# a repair function is exactly what a real mutational-spectrum split looks like.
# Masking these would destroy the signal.
#
# Use this list with annotate_sites.py --highlight, which flags sites falling in
# any of these genes without changing anything else:
#
#   annotate_sites.py --annotation NC_000962.3.gff3.gz --reference NC_000962.3.fna \
#       --positions <the mutations on your clade's defining branch> \
#       --highlight tb_repair_genes.txt
#
# ---------------------------------------------------------------------------
# GENE NAMES, AND LOCUS TAGS ONLY WHERE CHECKED -- NO COORDINATES.
#
# Names resolve against the annotation you supply (gene, Name, gene_synonym or
# locus_tag).  A name that is not in your annotation is reported as NOT FOUND,
# which is harmless; a misremembered locus tag would instead resolve to the
# wrong gene and quietly mislead you.  So the Rv numbers in comments are hints
# to check, not entries.  The few locus-tag ENTRIES (Rv1021, Rv1321, Rv0944,
# Rv2464c, Rv2228c) are genes NCBI's NC_000962.3 annotation names only by locus
# tag; each was checked against that annotation's product line.  Verify any
# you rely on against Mycobrowser or the NCBI H37Rv annotation.
# ---------------------------------------------------------------------------

# --- primary suspects: documented or suspected mutator phenotypes in MTBC ---
# mutT2 ~ Rv1160, mutT4 ~ Rv3908, ogt ~ Rv1316c, dnaE2 ~ Rv3370c,
# mutY ~ Rv3589, ung ~ Rv2976c, udgB ~ Rv1259
# The Beijing / lineage 2 background carries mutT2, mutT4 and ogt
# polymorphisms; check lineage before concluding anything from those.
#
# That warning earned itself on a 129k-sample MTBC tree.  The clade with the
# most striking hit -- one of only FIVE mutations on its defining branch was
# mutT4 R48G, a 12x enrichment -- turned out to be lineage2.2.1, i.e. Beijing.
# So the hit is the documented lineage marker, and it says nothing about
# whether mutT4 causes that clade's spectrum: the variant and the spectrum are
# both properties of lineage 2, and one branch cannot separate them.
#
# Check the lineage FIRST, before reading a repair-gene hit as a mechanism:
#
#   matUtils summary -i tree.pb.gz --sample-clades clades.txt
#   matUtils extract -i tree.pb.gz -I node_N -u node_N_samples.txt
#   grep -Fwf node_N_samples.txt clades.txt | cut -f2 | sort | uniq -c | sort -nr
#
# What would actually be evidence is independent recurrence: the same repair
# gene disrupted on an unrelated branch, with the same spectrum shift.  A
# single deep branch carries hundreds of lineage-defining mutations, so any
# one of them co-occurs with the spectrum by construction.

Rv1021  # mazG; NCBI names it only by locus tag
